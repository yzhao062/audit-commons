服务发现与限定范围的授权

在10月6日的初次公告之后，Meta 与 Sierra 于10月9日发布了个人智能体协议（Poppy）0.1版草案。企业通过 /.well-known/poppy.json 公布服务。智能体通过 HTTPS 客户端标识符与公钥确立身份，用户则通过支持的登录流程授予账户权限范围。

草案为 API 与对话采用绑定密钥的会话令牌及 DPoP 持有证明。MCP 端点使用限定资源的 Bearer 令牌，浏览器访问则以签名断言换取会话 Cookie。0.1版草案仍可能发生不兼容变更。Sierra 还公布了新增设计合作伙伴；参与伙伴提供反馈，并不证明已在生产环境部署。

应向实际实现索取的证据

我们的编辑部审计问题针对具体实现：用户授予了哪些账户权限，哪个服务收到哪项凭据，以及撤销授权能否在所有关联通道中阻止后续操作。协议文档本身无法回答这些问题。

核验时应结合授权记录、服务限定的令牌受众、浏览器会话和拒绝日志。可参照 NIST 的智能体身份研究及本站智能体行动工作表。Muse 权限披露提供了相关运行背景。
